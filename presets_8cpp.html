M5Unified's IMU_Class::begin(): for board_M5AtomS3R / board_M5AtomS3RCam / board_M5AtomS3RExt, accel/gyro get X/Y swapped plus Y inverted (axis_order_yxz | axis_invert_y), while mag gets X and Z inverted instead (axis_invert_x | axis_invert_z) – two different corrections from the same chip. This function applies the accel/gyro correction (AxisPermutation::YXZ, invert_y) via AhrsController::writeAxisOrder(), and the independent mag correction (invert_x | invert_z) via AhrsController::writeMagAxisOrder().

◆ unitBMM350()

bool m5::imu::presets::unitBMM350 ( AhrsController & ahrs,
m5::unit::UnitBMM350 & bmm350 )

Unit BMM350's magnetometer (U231), e.g. paired with a UnitMiniIMU for 9-axis.

Parameters
ahrsController to register bmm350 with
bmm350The GROVE Unit BMM350 (must already be begin()'d)
Returns
False if ahrs already holds the maximum number of sources (see AhrsController::add())

Determined on hardware; M5Stack's own U171 library never fuses its magnetometer, so there is no upstream mapping to transcribe for the GROVE magnetometers. The correction is the same 180-degree rotation about X that the DoF boards need (see unitDoF()): 

body = (mag_x, -mag_y, -mag_z)

Add the accel/gyro partner separately – a UnitMiniIMU needs no correction, its frame already matches this unit's (label up, GROVE connector nearest: +X right, +Y away from the connector, +Z out of the label face). Orient both units the same way, or apply the difference with AhrsController::writeUserAxisOrder().

M5Unified has no case for these units, so unlike the other presets here this one was determined on hardware. The BMI270 keeps the identity transform (its frame matches UnitMiniIMU); only the BMM350 needs a correction, a 180-degree rotation about X applied through the mag remap path: body = (mag_x, -mag_y, -mag_z). DoF6 (U228) is a bare BMI270 and needs no preset.
