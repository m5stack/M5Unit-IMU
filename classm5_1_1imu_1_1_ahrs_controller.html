Detailed Description

Merges up to 4 IMUDataSource instances by capability and fuses their samples into an attitude estimate via a pluggable AhrsFilterBase.

  • Capability merge: add() assigns each of Accel/Gyro/Mag/Temp to the first source that reports it ("first come, first served"); later sources reporting an already-claimed capability are still drained every update() (so their internal ring buffers do not overflow) but their samples for that capability are discarded.
  • Primary clock: the gyro-owning source drives the filter. Every update() call drains the gyro source fully; each popped gyro sample triggers one AhrsFilterBase::update() call, with the elapsed time divided evenly across the batch (dt / <samples drained this call>). The time of a call that drains no gyro sample is carried over to the next call that does, so calling update() faster than the gyro ODR does not shrink the integrated rotation. The carried-over time is capped at 0.5 s, so a stalled gyro source does not hand the filter one huge dt when it resumes. Accel/mag samples from a different source than the gyro are drained once per update() call and the resulting "latest" value is reused for every filter update() call in that batch (no per-sample interpolation across sources); a source shared with the gyro (e.g. a single 6/9-axis chip) is synchronized sample-for-sample instead.
  • Magnetometer overflow: a mag sample where any axis reads exactly -32768 (the BMM150 OVERFLOW sentinel) is rejected outright; the previous valid mag value is kept (both for latest() and for whatever gets passed to the filter). If no valid mag sample has ever been seen, the filter is fed mag == nullptr (6-axis operation).
  • Clocking: update() measures dt itself via m5::utility::micros() and smooths it with an exponential moving average (see ahrs_controller.cpp) before handing it to the filter, to avoid feeding raw, jittery sample-to-sample deltas straight into filters that resample their internal state on large dt swings (see vqf.hpp). update(const float dt) bypasses both the clock and the smoothing – the caller's dt is used as-is for the whole batch drained during that call, which is what callers with their own timebase should use.

◆ sleep()

bool m5::imu::AhrsController::sleep ( )

Put every added source into its lowest reversible power state.

Returns
True if at least one source actually slept

Calls IMUDataSource::sleep() on all sources, including those whose capability was not claimed. Sources that do not implement sleeping report false and are skipped, so a false return only means nothing could be suspended. Sleeping stops each source's periodic measurement; wakeup() powers the hardware back up but does not restart measurement – restart it explicitly on the units you want sampling again.

◆ tareYaw()

void m5::imu::AhrsController::tareYaw ( )

Zero the publicly reported yaw at the current heading.

Samples the active filter's current fused yaw (the same value quaternion()/euler() would derive from it) and stores a world-frame Z-axis rotation of the opposite angle as an internal tare offset. From then on every quaternion()/euler() call composes this offset on top of the filter's raw attitude, so the reported yaw reads ~0 right after this call while roll and pitch are unaffected. The filter's own internal attitude estimate – and, on a 9-axis setup, its alignment to magnetic north – is left untouched; only the publicly reported attitude is shifted. Calling this again re-zeros to whatever heading the filter has reached by then. See clearYawTare() to remove the offset. No-op (tare stays whatever it already was) if no filter has been selected yet.

◆ writeAutoCalibration()

void m5::imu::AhrsController::writeAutoCalibration ( const uint8_t accel,
const uint8_t gyro,
const uint8_t mag )

Enable/disable continuous background auto-calibration per capability.

Parameters
accelAccelerometer strength, 0 = off, 1-255 = adjustment speed (higher = faster)
gyroGyroscope strength, 0 = off, 1-255 = adjustment speed
magMagnetometer strength, 0 = off, 1-255 = adjustment speed
Note
Only the gyroscope is on by default (strength 1); accel and mag start at 0. An uncorrected gyro zero-rate offset is the dominant source of yaw drift and, when it exceeds VQFFilter::writeBiasClip()'s window, also stops VQF from estimating the bias on its own – so the default keeps it in check without any setup. Strength is effectively the per-sample follow rate x255 while the device is still, so 1 already converges with a roughly 1.3s time constant at a 200Hz sample rate.

A stillness/sphere-fit auto-offset algorithm operating on physical-unit samples. Each capability tracks how "still" its recent samples have been; once that stillness score exceeds a threshold, the offset is nudged toward fitting the sample to the expected shape at rest (accel/mag: a sphere of a fixed radius around the offset; gyro: the origin). The resulting offset is subtracted from every subsequent sample of that capability regardless of strength – setting strength to 0 only stops further adjustment, it does not clear a previously-converged offset (see writeCalibration()/clearing via calibration_data_t{}).

◆ writeMagCalibrationRadius()

void m5::imu::AhrsController::writeMagCalibrationRadius ( const float radius_ut)

Pin the field strength the magnetometer auto-calibration fits its samples to.

Parameters
radius_utLocal geomagnetic field strength in uT; pass 0 (or less) to go back to estimating it from the data, which is the default

The hard-iron fit works by pushing the offset until every sample sits on a sphere of this radius, so the radius has to match the field the device is actually in. Unlike the accelerometer's 1G sphere, that is not a universal constant: the geomagnetic field runs from roughly 25uT to 65uT depending on location, and a mismatched radius mis-scales the calibration rather than correcting it. By default the radius is therefore learned from the samples themselves; set it here when the local value is known (national geomagnetic surveys publish it) to skip the learning transient.

Note
Changing this resets the learned estimate, not the offset itself; clear the offset via writeCalibration() if a previous calibration converged against a different radius.

◆ writeUserAxisOrder()

void m5::imu::AhrsController::writeUserAxisOrder ( const AxisOrder & order)

Set a global user axis remap composed on top of every source's fixed order.

Parameters
orderPermutation and per-axis sign flip the caller wants applied to the reported frame

Mirrors M5Unified's IMU_Class::setAxisOrder user layer. writeAxisOrder()/ writeMagAxisOrder() carry the fixed, per-board correction (chip frame to a unified body frame); this order is applied after that, reorienting the whole device output frame, and so it affects Accel, Gyro, Temp and Mag of every source alike. The two are folded together internally (see compose() in axis_order.hpp), so no extra per-sample transform is paid. Defaults to the identity transform. Composition is recomputed here and on every writeAxisOrder()/writeMagAxisOrder()/add().
