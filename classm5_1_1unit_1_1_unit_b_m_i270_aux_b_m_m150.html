Detailed Description

BMI270 that switches on its auxiliary (AUX) interface and drives a BMM150 through it.

The BMI270's AUX interface is a general-purpose I2C master built into the chip – the datasheet calls it a "master interface hub for 1 I2C AUX sensor (e.g. ext. magnetometer, pressure)". This class implements one specific target, a Bosch BMM150: it addresses 0x10, checks for chip ID 0x32, reads that part's factory trim and drives its repetition/opmode registers. The name records that choice, since a different AUX target would need a different driver.

Which class to instantiate is a property of the board, not of the chip:

  • This class turns the interface on and probes for the BMM150. CoreS3 / AtomS3R / Mini IMU-Pro (U171) wire one there. Built-in IMUs in general should use it – the probe adapts to whatever the host actually carries, with no board table to keep up to date.
  • The plain UnitBMI270 never touches the interface. Use it where the wiring makes enabling it unsafe or pointless: on UnitDoF9 / UnitDoF10 the AUX pins are tied to the main I2C bus, so enabling them turns the BMI270 into a second bus master and the bus locks up until the unit is power-cycled; on UnitDoF6 there is simply no magnetometer.

Naming a chip here does not promise one is present – that is only known at runtime. On a host without a BMM150 (Capsule, StickS3, Core2 v1.3, ...) the probe finds nothing, the interface is switched back off, and the unit runs as a plain 6-axis BMI270. imuSpec() reports Mag only once a BMM150 has actually answered.

Note
The BMM350 in UnitDoF9 / UnitDoF10 / Unit BMM350 (U231) sits on the main bus, not on this interface, and is driven by UnitBMM350 instead
The bridge polls the BMM150 at a fixed 25Hz – the only rate the BMI270's aux_odr field and the BMM150's normal mode both offer – which bounds its usable oversampling; see config_t::aux_mag_preset

Write the repetition (oversampling) of the AUX BMM150.

Parameters
[in]rep_xyValue of REG_REP_XY (repetitions = 1 + 2 * rep_xy)
[in]rep_zValue of REG_REP_Z (repetitions = 1 + rep_z)
Returns
True if successful
Warning
Fails while periodic measurement is running, and fails for a pair the bridge's fixed 25Hz poll cannot complete in time (bmm150::repetition_fits()); unlike a stand-alone UnitBMM150 there is no slower rate to fall back on, so the ceiling here is absolute
Note
The value is applied to the magnetometer by the next startPeriodicMeasurement(). While measurement is stopped the bridge is not in a state where the BMM150's registers can be reached, so nothing is written to it here
